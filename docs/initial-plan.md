# 강현준 CRM 초기 구축 기준

현재 단계: 저장소 및 구축 문서 준비. 애플리케이션 구현·운영 데이터 이전·배포는 아직 수행하지 않았습니다.

## 제품 범위

- 병원 목록: 검색, 지역·진료과·관리 상태 필터, 병원 상세 정보와 검수 근거
- 제안서: 병원별 문서 버전, Notion 링크, 생성 상태와 본문 검수 상태
- 영업 진행: 단계, 담당자, 다음 액션, 예정일
- 연락 이력: 채널, 수신자, 승인, 실행 결과, 수신거부
- 작업 현황: 실행 상태와 업무 결과를 분리한 집계

## 이전 기준

2026-09-29 기존 CRM 점검 스냅샷 기준이며 실시간 수량은 아닙니다.

| 항목 | 점검 수량 |
|---|---:|
| Notion 현재 관리 병원 | 788 |
| 신규 한의원 | 100 |
| 제안서 링크 보유 병원 | 437 |
| 최신 100건 배치 저장·재조회 완료 | 74 |
| 기존 ERP 병원 원장 | 691 |

전체 관리 병원은 활성 영업 대상 수가 아닙니다. 보류·제외 기록을 포함합니다. 기존 ERP에는 신규 한의원 100곳이 빠져 있고, 사용자 제외 병원 3곳이 남아 있으며, Notion에 있는 제안서 링크 76건이 공란이었습니다.

## 데이터 설계 원칙

1. 기존 병원 ID와 외부 ID 대응표를 유지합니다. 병원명만으로 병합하지 않습니다.
2. 병원 적격 여부, 영업 단계, 제안서 생성·검수, 발송 승인·결과를 구분합니다.
3. 미확인, 없음, 접근 불가, 제외를 서로 다른 상태로 보존합니다.
4. 제안서는 병원당 단일 링크가 아닌 버전별 자산으로 관리합니다.
5. 원본 자료와 근거 확인일을 보존하고, 새 이관 데이터에서 먼저 대조합니다.
6. 사용자 제외 대상은 재수집·재생성하지 않으며, 식별 불가를 폐업으로 바꾸지 않습니다.
7. 수신거부와 승인·실행 이력을 이관하며, 불확실한 작업은 자동 재실행하지 않습니다.
8. 실제 병원 데이터, 연락처, 내부 문서 URL, 인증정보, 운영 로그는 코드 저장소에 일괄 복사하지 않습니다. 데이터 이전은 별도 검증 절차로 처리합니다.
