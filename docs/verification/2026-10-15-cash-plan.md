# Finance overview, assets and daily report

Three existing views restyled to match the transaction register. Asset cards show institution, masked account, correctly labeled balance/card credit limit/securities valuation and collection status (a failed collection newer than success is flagged). Daily report expands each account into inflow/outflow and day-by-day balances. No new navigation menus.

Available spending is an explicit 30-day plan, not a historical forecast or bank withdrawal guarantee. Basis is today's reported KRW non-loan bank accounts only; securities, FX and loans excluded. Historical-month overview separately fetches today's report. Missing/stale basis or incomplete numeric inputs suppress the result. User must confirm planned outgoings, reserve and restricted amounts; no assumed zero expenses, no unreceived income addition. Shortfall shown separately and spendable amount clamped at zero. Restricted deposits and uncollected liabilities require user entry. Optional local browser save is scoped by connection/company; restored plans require fresh confirmation. No provider data mutation or browser-to-cloud plan storage.

Automated tests cover exclusions, missing data, zero/negative cash, input validation, shortfall and asset collection failures. Existing authorization stays owner-only. No new schema or permission changes.

Later user clarification: primary objective is revenue, operating profit, net profit, debt-to-equity and reserve ratios. Added top financial KPI cards, input-source/as-of/business-type confirmation and period-scoped optional browser storage. Missing inputs remain unknown; tax omission suppresses net income, zero/negative equity suppresses leverage, zero capital suppresses reserve ratio, individual business excludes corporate reserve ratio. Current API docs provide category-based provisional aggregation guidance but no finalized balance sheet balances. No bank cash substituted for accounting earnings. Actual populated KPIs require confirmed same-business source records; source selection remains a user input. Calculation tests cover all formula paths and denominator edge cases.

User confirmed individual business (Business Anatomy) and Granter classification-based provisional aggregation. Added parallel bank/card/manual ticket + category reads. All source calls must return arrays before producing the draft; workspace mismatches rejected. Join category IDs to latest category definitions, aggregate signed directions by exact recognized profit subgroups. Exclude asset/liability/capital groups; unknown groups remain review rows. Only explicit included=true records counted. Dedup exact matching bank/card records connected by DEDUPLICATE_CHECK_CARD_USAGE; no fuzzy matching and no invoice/receipt addition. Refund direction preserved. All-unknown rows do not become zero earnings. Scope checkboxes allow removing personal assets, session-only. VAT, accrual, unreconciled duplicate and scope limitations visible. Net earnings stay pending until an explicitly confirmed tax estimate; corporate reserve ratio not applied to individual business. Test coverage includes reversals, duplicate links, asset exclusions and scope filters.
